# 随访计划

只处理输入材料、医生明确提供的信息和真实工具结果。产物必须是医生可直接审阅、修改的随访计划草稿，不能只复述病历或返回分析过程。

## 工作流程

1. 本 Skill 只能通过固定入口 `scripts/run.py` 执行。禁止 Agent 自行分析、生成临时脚本、调用模型补写内容或更改交付格式。
2. 固定脚本读取用户提供的文件或文件夹，确认患者/就诊边界、来源文件和任务目标；多个患者分别成段写入同一文件。
2. 识别字段标签和“本次就诊信息、医生初步判断、本次处置、医生明确的随访要求、患者限制”等标题区块，提取已明确的诊断或初步判断、症状、异常检查、当前处置、既有随访要求和患者相关限制。
3. 优先采用来源中明确存在的随访时间、方式、复查项目、观察指标和触发条件。
4. 来源未给出随访时间或项目时，不得自行伪造医嘱；填写“待医生确定”，并放入待医生确认项。
5. 不得把通用医学常识扩写成当前患者事项。来源只写“肾功能”时保持“肾功能”，不要擅自展开为肌酐、eGFR、尿常规；来源未写头痛、头晕、用药清单、生活方式或药物调整时，不得加入观察项目、执行提醒或待确认项。
6. 为关键事实保留来源文件名和原始文本；数值同时保留原始单位与标记。
7. 区分 `present`、`absent`、`not_mentioned`、`suspected`、`ruled_out`、`unclear` 和 `conflict`。
8. 直接输出每位患者的随访计划草稿，不要停留在“准备调用 Skill”“正在分析”或重复描述输入文件。
9. 草稿完成后必须在同一轮自动调用本 Skill 自带脚本生成 `.txt` 文件；不得等待用户再次提出保存或导出要求。

## 最小输出

每位患者至少包含：

- 患者标识
- 随访目的
- 建议时间：来源明确时原样保留，否则写“待医生确定”
- 随访方式：来源明确时原样保留，否则写“待医生确定”
- 观察项目
- 复查项目
- 异常触发条件
- 执行提醒
- 来源证据
- 待医生确认项
- `requires_human_review: true`

输入为多患者 Excel 时，逐行/逐病例输出，明确病例数量、成功数量和需要补充数量。不得因个别病例缺项而中止全部任务。

## 默认 TXT 交付

点击 Skill 广场“运行”后，CLINVEXA 本地服务直接执行固定脚本，不经过模型端点：

```powershell
python "$env:HERMES_HOME\skills\clinvexa\followup-plan\scripts\run.py" --source "D:\资料\病历资料.xlsx"
```

- 默认保存到来源文件所在目录，命名为 `<原文件名>_随访计划草稿.txt`，编码为带 BOM 的 UTF-8。
- `--source` 可传入文件或文件夹；只采用原文明确给出的随访字段，缺失项写“待医生确定”，不进行模型推断。
- 多患者内容按患者分段写入同一个 TXT，不拆成多个文件。
- 附件路径同样是有效来源路径；不得要求用户复制到其他工作区。
- 生成后重新读取文件，核对患者数量、核心字段、`requires_human_review: true` 和免责声明。
- 最终回复必须直接附上结果文件，并明确给出完整绝对路径；不得只在对话中展示计划。
- 文件未成功生成或验证失败时，不得宣称任务完成。

## 模型或工具失败

- 若模型端点返回 5xx、连接失败或超时，明确说明“当前模型服务不可用”，保留已提取材料并建议切换可用模型后重试；不得把该错误描述成 Skill 缺失。
- 所需读取工具未加载时返回“当前环境无该工具可调用”，并指出缺少的工具。
- 不得在上游失败时声称随访计划已经生成。

## 输出约束

- 不编造患者身份、时间、诊断、药物、检查、来源或随访事项。
- “待医生确认项”只能列出完成当前计划所必需、且确实因来源缺失而无法确定的字段；不得借此添加常规检查、生活方式、药物调整或其他通用建议。
- 不自动修正冲突、OCR 模糊内容、剂量单位或诊断确定性。
- 没有可靠来源时明确写明“依据不足”或“待医生确定”；所需工具未加载时返回“当前环境无该工具可调用”。
- 所有医疗结果设置 requires_human_review: true。
- 默认交付物必须是一个 `.txt` 文件，不生成 `.md` 或只返回聊天文本。
- 结尾附上：本结果仅用于信息辅助和人工审核，不作为临床诊断、处方或治疗决策依据。
