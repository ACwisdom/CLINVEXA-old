# 门诊病历草稿

把医生提供的原始材料整理成门诊病历草稿，不补写未提供的事实。

## 工作流程

1. 本 Skill 只能通过固定入口 `scripts/run.py` 执行。禁止 Agent 自行分析、生成临时脚本、调用模型补写内容或更改交付格式。
2. 固定脚本确认患者、就诊时间、来源编号和材料边界。
2. 保留原始转写，不修改否定词、时间、数值和单位；问句不能直接作为患者事实。
3. 同时识别字段标签、医患问答和医生明确结论。医患问答仅把患者回答归入与医生问题直接对应的字段；医生陈述只在明确表达判断、处置或复诊要求时进入对应字段。
4. 逐项提取固定九字段：主诉、现病史、既往史、过敏史、用药史、检查检验信息、初步判断、处置建议、随访计划。
4. 每条事实只能进入与其直接相关的字段，禁止把整段问诊记录重复填入多个字段。
5. 对未提及字段统一写“对话未涉及，待医生补充”，对不清楚的语音写“转写不清，待医生核实”，对冲突内容保留双方证据。
6. 输出固定九字段草稿、医生复核项和来源证据。
7. 草稿完成后必须在同一轮自动调用本 Skill 自带脚本生成 `.txt` 文件；不得等待用户再次提出保存或导出要求。

## 固定输出协议

协议版本：`clinvexa.consultation-draft.v1`；输出语言：简体中文。

```text
主诉：
现病史：
既往史：
过敏史：
用药史：
检查检验信息：
初步判断：
处置建议：
随访计划：
医生复核项：
来源证据：
```

## 失败处理

材料不可读、转写为空或患者边界无法确认时，返回失败原因与需补充材料，不得生成虚构草稿。

## 默认 TXT 交付

点击 Skill 广场“运行”后，CLINVEXA 本地服务直接执行固定脚本，不经过模型端点：

```powershell
python "$env:HERMES_HOME\skills\clinvexa\outpatient-note-draft\scripts\run.py" --source "D:\资料\门诊记录.txt"
```

- 默认保存到来源文件所在目录，命名为 `<原文件名>_门诊病历草稿.txt`，编码为带 BOM 的 UTF-8，便于 Windows 中文软件直接打开。
- `--source` 可传入文件或文件夹；文件夹内多份资料合并生成一份草稿汇总文件。
- 提取原文明示的字段标签、医患问答事实和医生明确结论；未提及统一写“对话未涉及，待医生补充”，不进行模型推断。
- 附件路径同样是有效来源路径；不得要求用户复制到其他工作区。
- 生成后重新读取文件，确认九字段、`requires_human_review: true` 和免责声明均存在。
- 最终回复必须直接附上结果文件，并明确给出完整绝对路径；不得只说“已保存到文件中”。
- 文件未成功生成或验证失败时，不得宣称任务完成。

## 输出约束

- 不新增诊断、药物剂量、医嘱或治疗结论。
- 录音或 OCR 不清晰时标记 `unclear`，不要猜测。
- 结尾设置 `requires_human_review: true`。
- 结尾附上：`本结果仅用于信息辅助和人工审核，不作为临床诊断、处方或治疗决策依据。`
