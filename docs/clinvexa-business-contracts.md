# CLINVEXA 业务合同管理

桌面端的「合同管理」使用本机 CLINVEXA 服务。草稿、材料摘录、预审结果和流转记录保存在当前 CLINVEXA 数据目录下的 `clinvexa/contracts/contracts.sqlite3`。该台账以当前运行实例为单位。

## 合同流程

1. 新建业务合同，选择起草模板，填写名称、相对方、项目编号、金额和履约期限。系统固定信息随正文提交到 OA，正文可编辑或导入。内置模板用于试运行，医院验收时应使用院方确认的模板。
2. 按类型导入招标文件、响应文件和中标通知书。支持 TXT、DOCX 和含文本的 PDF，单个文件上限为 40 MB，提取后的文字上限为 20 万字。扫描件可以将核对后的文字录入材料摘录。
3. 保存草稿并运行规则预审。核对招采方式和前置审批记录，检查已提取的项目编号、合同相对方、金额和常见条款。相对方或金额等字段与材料冲突时，需要修订后重新预审。无法识别的字段提示人工核对。可查看历史版本、比对正文、导出带水印的 PDF。
4. 配置 OA 测试接口后可发起测试审批。也可在 OA 手工提交，然后登记流程编号。若接口调用没有返回有效编号，先在 OA 核实创建结果。确认没有创建流程并登记核实说明后，才可再次提交。
5. 在 OA 核实审批结果后登记。通过的合同可以导出清洁版，登记用印件，核对后归档。退回的合同可以重新起草。台账支持搜索、CSV 导出、归档和续签提醒。

## 智能合同预审

1. 在合同卡片选择合同类型、院方主体、金额方向、是否确定金额和资金来源。收入或支出且金额确定时填写固定金额。核对自动提取的字段并保存。
2. 导入 TXT、DOCX 或文本 PDF。原件随合同保存在本机 SQLite。风险引文可定位到 PDF 页、DOCX 段或 TXT 行。改写后的正文按保存版本显示行号。对扫描页、空文件及读取失败的文件，界面显示具体读取范围。
3. 在「智能合同预审」创建规则任务。配置院内模型后可选规则与模型任务。查看覆盖范围和风险原文，逐项登记确认、驳回或补证。复核姓名为本机登记。
4. 生成并保存独立报告，导出 CSV。重新打开合同后，从「审查历史」选择任务及报告。旧报告保存生成时的决定，更新复核后可生成新报告。

适用招采时，先核对同项目的可读文件，再比对中标相对方与适用的固定金额。扫描件、人工摘录和缺少依据的项目显示待核验。OA 流程继续使用「送审前规则检查」和原合同状态。验证记录见 [P0 实施报告](research/contract-preaudit/10_P0_IMPLEMENTATION_REPORT.md)。

## 云桌面部署

通用 Windows x64 离线包的最低系统版本为 Windows 10 22H2。瑞金云桌面实际为 Windows 10 企业版 LTSC 64 位，Build 17763。部署到该环境时使用文件名包含 `vdi-win1809` 的离线包。首次安装使用完整包，已有匹配的 2.0.10 安装时可使用对应升级包。兼容包的安装和应用启动需在该云桌面实测。医院员工打开 CLINVEXA，从侧栏进入「合同管理」，使用院方测试合同材料核对草稿、版本、用印件和台账，再在院内 OA 核验流程。

经授权的法务运行实例可由部署管理员配置 `CLINVEXA_CONTRACT_ROLE=legal`。该设置属于本机实例，医院多人试用时须核实不同岗位的访问边界。独立演示数据通过 `CLINVEXA_CONTRACT_DEMO=1` 启用，使用单独台账，关闭该设置后重启进入实际联调环境。

## 院内模型

以下环境变量由 CLINVEXA 服务进程读取。设置后重新启动桌面端。

| 环境变量 | 值 |
| --- | --- |
| `CLINVEXA_CONTRACT_MODEL_URL` | 院内模型的兼容 API 基础地址，带 `/v1`，或完整的 `/chat/completions` 地址 |
| `CLINVEXA_CONTRACT_MODEL_NAME` | 模型服务登记的模型名 |
| `CLINVEXA_CONTRACT_MODEL_KEY` | 院内模型 API 密钥 |

创建「规则与模型审查任务」时发送待审正文、适用条款类别和必要的合同上下文。模型建议经过结构和原文校验后进入逐项复核。模型超时或校验失败时保留规则结果，并显示模型未完成原因。

## OA 测试接口

配置依据为院方提供的泛微 E9 流程创建接口说明。[泛微 API 目录](https://e-cloudstore.com/ec/api/applist/index.html#/)用于联调时核对可用接口。在云桌面打开院方 OA 测试门户，从「新建申请 → 合同管理 → 业务合同」核实实际表单。OA 网页测试账号用于页面操作。接口使用独立的调用凭据、测试流程 ID 和真实字段映射。经办人在 OA 核验状态后登记回执。合同送审直接调用 E9 API。

| 环境变量 | 值 |
| --- | --- |
| `CLINVEXA_CONTRACT_OA_TEST_URL` | OA 测试基础地址或完整的 `/api/workflow/paService/doCreateRequest` 地址 |
| `CLINVEXA_CONTRACT_OA_WORKFLOW_ID` | 测试业务合同流程 ID |
| `CLINVEXA_CONTRACT_OA_FIELD_MAP` | JSON 对象。键可用 `title`、`counterparty`、`amount`、`project_number`、`body`，值为 OA 字段名。至少映射相对方、金额和正文 |
| `CLINVEXA_CONTRACT_OA_APPID` | E9 接口许可证编号 |
| `CLINVEXA_CONTRACT_OA_TOKEN` | E9 当前有效的调用令牌 |
| `CLINVEXA_CONTRACT_OA_USERID` | 按 E9 接口要求用注册公钥加密后的用户标识 |

院内验收使用一份真实业务场景的测试合同和对应招采材料。医院员工在 OA 核实请求编号、发起人与审批人、字段和所需附件，实际走一次通过并归档、一次退回再送审。网络超时时先在 OA 核实是否已创建流程。当前自动创建只提交表单字段，OA 附件由经办人按院方流程处理。实际验收记录以 OA 中可打开的流程及审批记录为准。
