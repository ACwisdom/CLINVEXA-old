## 本阶段交付范围

1. 问诊转写先按语义片段拆分，再依据原文证据生成九字段病历草稿。
2. 未从问诊对话中识别到的字段统一显示“对话未涉及，待医生补充”。
3. “交给病历 Agent 深度整理”先进入全新会话，再提交给 `medical_record` Agent。
4. 唯一源码 A、软件 A 内置运行时和本机实际运行目录完成一致性同步。

## 已交付功能

- 病历草稿最少包含：主诉、现病史、既往史、过敏史、用药史、检查检验信息、初步判断、处置建议、随访计划。
- 支持普通中文标点以及中文语音识别常见的小型逗号 `﹐`，避免整段转写被误当成一个句子。
- 主诉只选取正向症状与病程证据；现病史提取症状演变及伴随表现。
- 既往史、过敏史、用药史、检查检验、判断、处置和随访使用独立证据规则。
- 检查检验字段会排除“否认高血压”等慢病史片段，避免字段串线。
- 初步整理不补造诊断、用药或处置事实，草稿继续保留医生复核提示。
- 病历 Agent 交接提示中明确限定只使用本次问诊材料，不沿用上一会话内容。

## 2026-08-10 独立会话持久化补充验收

手工验收反馈显示，原实现虽然先调用了“新会话”动作，但 `/new` 路由切换与首条提交并发，触发了会话防串线保护；新建的运行时会话因此被主动关闭，没有首条持久化消息，也不会出现在左侧“会话”列表。

本次已将流程改为：

1. 清空旧会话运行绑定，但暂不导航到 `/new`。
2. 显式调用 `session.create` 并等待返回真实运行时会话 ID 与持久化会话 ID。
3. 新会话立即以问诊整理任务作为侧栏预览写入会话列表。
4. 将首条病历整理任务定向提交到刚创建的运行时会话。
5. 只有新会话创建及提交成功后，才关闭问诊记录窗口。

补充验收结果：

- 新建持久化会话与精确定向提交测试：2/2 通过。
- 保持当前路由、清除旧会话绑定测试：1/1 通过。
- 问诊界面及 CLINVEXA 桌面回归：12/12 通过。
- Renderer 与 Electron 类型检查：通过。
- 正式软件重新构建成功；当前 1 个主进程、1 个 8001 监听、27 个 Skill，进程响应正常。
