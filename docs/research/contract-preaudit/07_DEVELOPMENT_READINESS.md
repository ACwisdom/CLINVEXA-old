# 开发准备度

可以进入第二阶段的本地 P0 开发。现有合同 UI、FastAPI 入口、SQLite 版本及导出已提供足够接缝。院内正式验收条件和自动 OA 联调尚未齐备。

| 项 | 当前准备度 | 前置动作与通过证据 |
| --- | --- | --- |
| 源码基线 | 可开始 | 以工作树 2.0.11 为起点，保全未提交代码。工程负责人决定如何固化基线，记录版本及新增迁移策略 |
| 业务合同样本 | 部分 | 院方提供脱敏合同正文、批准模板、无金额/不确定金额/多版本等对照。建立法务标注和合格规则列表 |
| 招采材料 | 部分 | 2234 三份材料可用。对扫描件提供核验摘录或院内 OCR，补同项目脱敏合同和前置审批关联 |
| 文档及规则 | 有基础 | 补页/段定位、规则版本和分条件的合同要素定义。附上反例和日期、金额单位的边界 |
| VDI 安装 | 包已校验传入 | 云桌面实际安装后打开合同页，实测上传、预审、复核、重开和导出。复核 C 盘、路径及网络可达性 |
| 模型与 OCR | 未实测 | 院方授权服务端点、模型版本、凭据下发与数据范围。用无敏感合成材料测超时、格式和失败降级 |
| 权限和留痕 | 单实例基础 | 确认人员和角色来源。审批、法务建议、证据和导出权限在服务端验证，约定留存和审计责任 |
| E9 | 文档及流程号已知 | 获取 273 的完整表单、字段和枚举、附件映射、流程身份与权限、授权测试记录及读接口。自动送审独立联调 |

实施顺序建议为：冻结可复用基线与样本 → 先实现可定位的规则预审与人工复核 → 接模型候选和错误降级 → 用 2234 验证关键字段一致性 → 在云桌面离线安装与验收 → 按批准范围接真实 OA。外部数据、部署和授权未齐时，本地先用合成记录验证契约及行为，不以模拟回执验收 OA。

当前可复现命令与局限见 [08](08_EVIDENCE_INDEX.md)。交接给下一位 AI 请先读 [09](09_HANDOFF_TO_CHATGPT.md)，再读 [05](05_P0_SCOPE_AND_GAPS.md) 和 [06](06_API_AND_DATA_CONTRACTS.md)。
