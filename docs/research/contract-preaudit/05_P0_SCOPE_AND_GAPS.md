# P0 范围、缺口与验收

P0 交付目标是让经办人或法务从合同文档开始，获得有出处的预审清单，逐项复核并保留可再打开的记录。沿用需求中业务合同范围，科研、资产、知识产权合同另行处理。全流程功能已在建设范围内，按本轮任务要求分期。

1. 导入经授权的合同 DOCX、文本 PDF，分别关联招采材料。保存版本与文档标识，遇到扫描件提供明确提示和人工录入位置。
2. 识别项目号、相对方、金额、日期及关键条款。人工确认歧义。收入、支出、无金额、金额未确定的条件规则按院方确认版本执行。
3. 执行必备要素和条款检查、关键字段对照、语义风险候选。每项有等级、原因、规则依据、证据位置和可执行修改建议。
4. 逐项确认、驳回或补证，保存复核人员、时间、理由和最终清单，导出可回溯报告。保留之前版本，编辑合同后发起新任务。
5. 把失败、部分完成、未提供材料和待人工核验明确展示。模型或 OCR 不可用时保存已得到的规则结果和未完成原因。

| 类别 | 交付决策 |
| --- | --- |

| 必须改造 | 解析保留页段/表格锚点，按合同类型和金额条件走规则。审查输出从自由文本升级为可验证证据。工作区展示逐项复核、缺失数据及可追溯报告。旧草稿和旧审查数据可读 |

## 招采一致性单独决策

现有三份 2234 招采材料同项目。招标文件可以抽取项目号，中标通知书和 422 页技术响应件为扫描件，当前解析不能自动提取。样本目录中未见对应正式合同正文，OA 实际关联记录尚未核验。首版**条件纳入**项目编号、相对方、中标金额的关键字段一致性，前提是提供脱敏合同，使用带页码和核验记录的人工摘录或经过验证的院内 OCR。缺任一必要证据时输出“未完成比对”并提示原因。全文技术承诺、付款与验收条款、实时 OA 附件同步保持在需求清单，随样本和权限成熟后纳入。

## 建议验收协议

以下为待院方确认的建议门槛，不是已测指标。固定模型、规则版本、样本、硬件和计时起点。由经办与法务共同标注，分文本、扫描、招采匹配、冲突、缺材料和超时单独报告。建议首批至少 30 份经授权样本，关键风险正例至少 20 项，小样本必须同时报分子和分母。

| 项 | 建议通过条件 |
| --- | --- |
| 解析与要素 | 文本样本关键字段准确率 ≥95%，金额、日期和供应商逐字段报数。扫描样本单列；低置信或不可解析时全部标为待核验 |
| 风险质量 | 关键风险召回率 ≥90%（命中/标注关键风险）；误报占已报发现 ≤15%（错误发现/全部发现），各级别分别报告 |
| 原文定位 | 存在性校验 100%（引文与快照匹配），经人工核对正确位置 ≥95%。缺失类标出覆盖范围和查找依据 |
| 审查依据 | 100% 规则引用可找到批准版本。模型建议不得被包装成缺失依据的确定结论 |
| 性能与异常 | 建议 20 页以内文本合同本地规则 P95 ≤10 秒，含院内模型 P95 ≤60 秒。OCR 另计。超时、损坏、断网、重复发起、退出重开均可复核已有进度 |
| 人工留痕 | 每项决定可追溯至人员、时间、理由和输入版本。导出与当前任务一致，旧版本可重开，越权查询拒绝 |
| 院内验证 | 兼容包在 Build 17763 云桌面启动，完成导入到报告。涉及 OA 的验收另用授权测试流程核对实际编号、字段、附件和轨迹 |
