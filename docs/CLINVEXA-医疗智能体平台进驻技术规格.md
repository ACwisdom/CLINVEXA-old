# CLINVEXA 进驻医疗智能体平台技术规格

## 1. 产品与接口身份

| 项目 | 要求 |
|---|---|
| 产品名称 | CLINVEXA 医疗 AI 办公助手 |
| 桌面系统 | Windows 10/11 x64 |
| Agent 接入 | OpenAI-compatible 模型端点；本地 Agent 网关采用 HTTP/WebSocket |
| 医疗服务 | 本机 `127.0.0.1:8001`，提供 Skill、问诊、病历与 RPA API |
| 数据类型 | 文本、Office/PDF、图片/截图、中文音频、Agent 会话与工具结果 |
| 交付形态 | 单体桌面客户端 + 随包 Python 运行时 + 医疗 Skill + 中文 ASR + Computer Use 驱动 |

## 2. 模型能力要求

### 文本/Agent 主模型

- **最低可用**：7B 参数级指令模型，4-bit 量化；至少 16K 上下文；支持稳定的 JSON/工具调用和流式输出。
- **推荐生产**：14B–32B 参数级模型，至少 32K 上下文；中文医疗文本能力良好；多轮工具调用、长文档摘要和结构化输出稳定。
- **高质量复杂任务**：32B 及以上，适合长病历、多文档汇总、科研资料整理和复杂多 Agent 编排。
- 模型必须通过 OpenAI-compatible API 暴露；模型 ID、上下文长度和限流信息应由平台登记。

7B 是工程接入最低门槛，不等于医疗效果验收门槛。正式上线应以脱敏金标准集上的事实抽取、漏项、幻觉、工具调用成功率和医生复核结果决定是否可用。

### 视觉模型

- **最低可用**：7B 参数级多模态模型，可理解中文界面截图、表格、检查报告截图和常见 HIS 布局。
- **推荐**：7B–14B 多模态模型，支持高分辨率图片、OCR 后联合推理和多图输入。
- 视觉模型用于截图理解和 UI Automation 失效时的兜底；不能仅凭截图自动确认患者身份或直接提交正式病历。

### 中文语音识别

- 软件已随包提供 faster-whisper medium 中文转写资源，不需要语音大模型或云 ASR 才能工作。
- 平台可选接入院内 ASR，但输出必须规范为简体中文，并保留原始音频/转写关联和人工校正入口。

### Embedding/Reranker（可选）

- 基础版本不是硬依赖；接入院内知识库时建议配置中文/多语种 Embedding 和 Reranker。
- 推荐向量维度 768 及以上，单次检索后重排 20–50 条候选；最终回答必须保留来源。

## 3. 最小与推荐部署资源

### A. 云模型/院内远程模型模式（桌面工作站）

| 资源 | 最低 | 推荐 |
|---|---:|---:|
| CPU | 4 核 x64 | 8 核及以上 |
| 内存 | 16 GB | 32 GB |
| 可用磁盘 | 10 GB | 20 GB 以上 |
| GPU | 非必需 | 视觉预处理可选独显 |
| 网络 | 可访问模型 HTTPS 端点 | 稳定低延迟专网/互联网 |

此模式由远程端点承担文本/视觉推理，本机运行 UI、Agent、Skill、ASR、文件处理和 Computer Use。

### B. 本地 7B 模型模式

| 资源 | 最低 | 推荐 |
|---|---:|---:|
| CPU | 8 核 | 16 核 |
| 内存 | 32 GB | 64 GB |
| GPU 显存 | 12–16 GB（4-bit 7B） | 24 GB |
| 可用磁盘 | 30 GB | 60 GB |

### C. 本地 14B–32B 满血模式

| 资源 | 最低 | 推荐 |
|---|---:|---:|
| CPU | 16 核 | 24 核以上 |
| 内存 | 64 GB | 128 GB |
| GPU 总显存 | 24 GB（14B 4-bit） | 48–80 GB（32B 4/8-bit及视觉模型） |
| 可用磁盘 | 80 GB | 150 GB 以上 |

双卡部署时必须由推理框架完成张量并行/流水线并行验证，不能只按显存相加判断可用。N260 实机型号、驱动、推理框架和量化格式应另做兼容性验收；当前软件交付默认先使用 OpenAI-compatible 远程端点。

## 4. 网络、端口与依赖

- 本地固定医疗服务：`127.0.0.1:8001`，仅监听回环地址。
- Agent 网关：默认动态本地端口，由桌面主进程发现并通过令牌连接。
- 外联：用户配置的模型提供方 HTTPS 443；不应把本地 8001 暴露到院外网络。
- 随包依赖：Electron、Python 3.11 运行时、Python 锁定依赖、Node/浏览器自动化资源、Playwright Chromium、faster-whisper medium、cua-driver、27 个内置 CLINVEXA Skill。
- API Key 和医院凭据不进入源码或安装包，由平台密钥管理或用户本机设置提供。

## 5. 平台需要登记的关键信息

1. 应用 ID、版本、安装包 SHA-256、源码身份 SHA-256、发布人和发布日期。
2. 模型提供方、Base URL、模型 ID、上下文、工具调用能力、视觉能力、并发与限流。
3. 数据分类：患者信息、音频、截图、文档、会话、日志；各自存储位置、保留期、删除与备份策略。
4. 工具清单及权限：文件、浏览器、Computer Use、HIS RPA、Skill；高风险动作确认策略。
5. HIS 目标版本、窗口标题、患者核对字段、页面路径、控件定位、保存/提交确认点。
6. 运行健康接口、日志路径、故障恢复、升级/回滚、离线安装和卸载策略。
7. 医疗验收集、成功率、延迟、幻觉/漏项标准、医生复核责任和免责声明。

## 6. 上线验收最低标准

- 双击客户端后 Agent 网关、8001 医疗服务、中文语音和 Computer Use 自动启动；重复启动不产生第二套主进程或重复端口服务。
- 模型连接测试、流式对话和工具调用成功；切换模型后仍保持 CLINVEXA 身份和简体中文输出。
- 27 个内置 Skill 可检索、安装、启用和运行；`skill-creator` 生成的 Skill 能进入广场。
- Word/Excel/PDF/图片预览无二进制乱码；问诊九字段草稿和新会话深度整理闭环成功。
- HIS RPA 能识别患者、填入草稿、验证页面状态并在正式提交前等待医生确认。
- 普通 Computer Use 操作不中断；文件外发/上传明确确认；危险删除和危险命令硬阻断。
- 安装、首次初始化、进入 Agent、退出、再次双击启动、卸载均有记录且无残留旧入口。
